# constraints-release.txt -- reproducible release dependency lock.
#
# Exact versions resolved in the known-good Windows build venv
# (.venv-release, docs/RELEASE.md "Release venv") that produces the shipped
# installer. Consume as a pip CONSTRAINTS file:
#   pip install -r requirements-dev.txt -c constraints-release.txt
#   pip install -e .                    -c constraints-release.txt
#   pip install "pyinstaller>=6.10"     -c constraints-release.txt
# so two builds of the same tag resolve a byte-identical dependency set.
#
# This is a CONSTRAINTS file, NOT a requirements file: it only caps the
# version of a package that something else is already installing; it does
# not itself install anything. yamabiko/requirements.txt keeps its version
# RANGES (that is the library's runtime metadata) -- this file pins what
# those ranges actually resolved to for the release build.
#
# Wired into the release path only: installer/build.ps1 (prereqs) and
# .github/workflows/installer-smoke.yml. The lightweight ci.yml does NOT
# use it -- contributor PRs resolve against the ranges so a routine dep
# bump is not blocked by a stale lock.
#
# Python: 3.12 (3.12.10)    Platform: win_amd64
# Regenerate after any intentional dependency change, from the build venv,
# then restore this header:
#   .venv-release\Scripts\python.exe -m pip freeze --exclude-editable > constraints-release.txt
